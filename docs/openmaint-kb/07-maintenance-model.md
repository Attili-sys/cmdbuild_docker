# 07 — Maintenance Model

**Source:** API `/processes`, `/classes`, DB `_Job`, domain analysis  
**Classification:** STANDARD OPENMAINT

---

## Overview

openMAINT implements two maintenance process types:

| Type | Class | Description |
|------|-------|-------------|
| Preventive Maintenance | `PreventiveMaint` | Scheduled, planned maintenance generated by the PM engine |
| Corrective Maintenance | `CorrectiveMaint` | Reactive, demand-driven maintenance from a request or fault |

Both are workflow processes (subclasses of `MaintProcess → Process → Activity`).  
Both share a set of workflow states managed by the CMDBuild BPMN engine.

---

## Preventive Maintenance

### Configuration Chain

PM follows a strict configuration chain that generates work orders automatically:

```
PrevMaintDef  (what to do — task definition / activity template)
       ↓
PrevMaintConfig  (when, where, who — schedule configuration)
       ↓  [automated by PrevMaintGeneratorScheduler job at 05:00 UTC daily]
PreventiveMaint  (work order — process instance)
       ↓  [automated by PrevMaintAdvanceScheduler job at 06:00 UTC daily]
PrevMaintTask  (individual task within the work order)
```

### PrevMaintDef — Activity Definition

| Attribute | Type | Notes |
|-----------|------|-------|
| Code | string | |
| Description | string | Name of the maintenance activity |
| Notes | text | |

The definition holds the tasks (`PrevMaintTask`) via domain `PrevMaintDefTask`.  
Tasks define what the technician does: checklists, measurements, inspections.

### PrevMaintConfig — Schedule Configuration

| Attribute | Type | Notes |
|-----------|------|-------|
| Name | string | Required |
| Site | reference → Site | **Required** — which location |
| CISubset | reference → CISubset | **Required** — which assets |
| PrevMaintDef | reference → PrevMaintDef | **Required** — which activity definition |
| Team | reference → Team | **Required** — who executes |
| Company | reference → Company | Optional — which company |
| MaintManual | reference → MaintenanceManual | Optional documentation |
| Frequency | integer | **Required** — number of frequency units |
| FrequencyUM | lookup [PrevMaintConfig - FrequencyUM] | days / weeks / months / years |
| FirstDueExecDate | dateTime | **Required** — first due execution end |
| FirstOpeningDate | dateTime | **Required** — first work order opening |
| FirstExpExecDate | dateTime | **Required** — first expected start |
| EndValidityDate | dateTime | When the schedule expires |
| Forewarn | integer | Days before due date to open the work order |
| Duration | decimal | Expected duration |
| ModifyAction | lookup [PrevMaintConfig - ModifyAction] | KeepManual / UpdateAll |
| Active | boolean | Enable/disable the schedule |

### PrevMaintTask — Individual Checklist Tasks

| Attribute | Type | Notes |
|-----------|------|-------|
| Description | string | Task description |
| Outcome | lookup [PrevMaintTasks - Outcome] | Ok / Ko / Done / ToDo |

Tasks are linked to PrevMaintDef and appear within each generated PreventiveMaint work order.

### PreventiveMaint — Work Order (Process)

The PreventiveMaint process is auto-generated by the scheduler. It follows workflow states.  
Source: `Process - ProcessStatus` lookup has 16 values covering both CM and PM states.

Key PM states (from `Process - ProcessStatus` lookup):
- `PM-Execution` — the execution phase  
- Other states are managed by the BPMN engine

Process attributes include location, asset, schedule references, dates, team, costs.

## Corrective Maintenance

### Corrective Maintenance States

The corrective maintenance process (`CorrectiveMaint`) goes through these states (from `Process - ProcessStatus` lookup):

```
CM-Opening → CM-Assignment → CM-Management → CM-Estimate → CM-Control → CM-Closure
```

Plus sub-states visible in process actions:
- `CM-Assignment_Advance`, `CM-Assignment_Split`, `CM-Assignment_Duplicate`, `CM-Assignment_Reject`
- `CM-Management_Advance`, `CM-Management_EmptySuppliers`
- `CM-Estimate_Advance`, `CM-Estimate_EmptyCosts`
- `CM-Control_Advance`, `CM-Control_EmptySubtasks`

### Process Types and Outcomes

| Lookup | Values |
|--------|--------|
| `MaintProcess - Type` | Breakdown / Damage / Extraordinary |
| `MaintProcess - Outcome` | Positive / Negative / Canceled |
| `MaintProcess - SuspensionReason` | Supplier / Replacement / Other |
| `MaintProcess - EstimateStatus` | CM-Accepted / CM-Rejected / CM-Received / CM-Expected / CM-Declined |

### MaintSLA — SLA Configuration

Each CorrectiveMaint (and PreventiveMaint) work order can be subject to one or more SLAs via domain `ProcessMaintSLA`.

| Attribute | Type | Notes |
|-----------|------|-------|
| ProcessClass | lookup [COMMON - Classlist] | Which process type this SLA applies to |
| Priority | lookup [COMMON - Priority] | 1 (highest) to 4 (lowest) |
| Threshold | integer | SLA time limit |
| ThresholdUM | lookup [MaintSLA - ThresholdUM] | Seconds / Minutes / Hours / Days / Weeks / Months |
| TimeCalcCriteria | lookup [MaintSLA - TimeCalcCriteria] | System (clock time) or Calendar (working hours) |
| StartFromProcState | lookup | Which process state starts the SLA timer |
| StopToProcState | lookup | Which state stops the timer |
| IgnoredStates | lookupArray | States where timer pauses |
| ResetStates | lookupArray | States where timer resets |
| MaintSubcategory | reference → MaintSubcategory | Optional — applies only to this subcategory |
| Site | reference → Site | Optional — applies only to this location |
| Contract | reference → Contract | Optional — links SLA to a contract |
| Team | reference → Team | Optional — applies to this team |
| Active | boolean | |

SLA status per work order is tracked in `ProcessMaintSLA` table with states: Ongoing / Paused / Concluded.

## Maintenance Categories

Work orders are categorized using:

| Class | Purpose |
|-------|---------|
| `MaintCategory` | Top-level category (e.g., HVAC, Electrical, Cleaning) |
| `MaintSubcategory` | Sub-category linked to MaintCategory |
| `Topic` | Knowledge base entries linked to categories and work orders |

Categories drive:
- Corrective maintenance configuration (`CorrectMaintConfig` / `CatCorrectMaintConf` domain)
- SLA assignment (`MaintSubcatMaintSLA` domain)
- Work order classification

## Maintenance Teams and Resources

| Class | Purpose |
|-------|---------|
| `Team` | Maintenance team — has a Supervisor (Employee reference), Company, email, calendar |
| `InternalEmployee` | Internal technician |
| `ExternalEmployee` | External technician |
| `SupplierEmployee` | Technician belonging to a supplier |

Teams are linked to work orders via domains:
- `TeamMaintProcess` — team assigned to work order
- `TeamPrevMaintConfig` — team on PM schedule
- `TeamCorrMaintConfig` — team on CM configuration
- `TeamsEmployees` — employees in team
- `SupervisorTeam` — employee as team supervisor

A work order can also have a Requester (via `RequesterMaintProc` domain) — the person who raised the request.

## Maintenance Costs

Costs in openMAINT are tracked through `AccountingMov` (accounting movements):

| Subclass | Purpose |
|----------|---------|
| `GenericAccMov` | Generic cost/revenue entry |
| `LabourAccMov` | Labour cost |
| `MaterialAccMov` | Material cost |

Key accounting attributes:
- State: Estimate / Actual
- Type: Cost / Revenue
- Linked to work order via domain `MaintProcAccMov`
- Linked to site via `SiteAccMov`
- Linked to contract via `ContractAccMov`

Price lists (`PriceList` / `LabourPriceList` / `MaterialPriceList`) define standard rates used when generating cost estimates.

## Maintenance Manuals and Checklists

| Class | Purpose |
|-------|---------|
| `MaintenanceManual` | Document/manual linked to PM configs (`MaintManualPrevConf` domain) |
| `PrevMaintTask` | Individual checklist task within a PM definition |
| `PrevMaintTasks` | Tracks task execution status (Ok/Ko/Done/ToDo) per work order |
| `Topic` | Knowledge base entry (Checklist / Documentation / FAQ / Guide / Troubleshooting) |

Topics can be linked to categories (`MaintCatTopic`), subcategories (`MaintSubcatTopic`), and work orders (`MaintProcessTopic`).

## AJMN Notes

- **Preventive maintenance is fully supported** with automated scheduling
- **Corrective maintenance** supports multi-state workflow with assignment, management, estimate, and control phases
- **SLA tracking** supports both clock-time and calendar-time calculation
- **Cost tracking** (estimate vs actual) is built in through AccountingMov
- **Team assignment** is supported with multi-employee teams
- **Material consumption** links to warehouse movement — see `09-inventory-and-logistics.md`
- **Checklists** exist via PrevMaintTask
- **Approval workflow** in corrective maintenance includes estimate approval state
- **Notifications**: email templates exist but no accounts configured in this POC
